The `llm` section of `lawbook.yaml` chooses the model that judges
[`standard` rules](/llm-rules). It is optional; these are the defaults:

```yaml
llm:
  provider: bedrock
  model: anthropic.claude-opus-5-5
  concurrency: 4
  maxBytes: 131072
  cache: true
```

| Key           | Meaning                                                                                        |
| ------------- | ---------------------------------------------------------------------------------------------- |
| `provider`    | `bedrock` (default), `anthropic`, or `openai`.                                                 |
| `model`       | The model id in the provider's own naming. Defaults per provider, see below; `openai` has no default, so `model` is required. |
| `region`      | Bedrock only. The AWS region; else `AWS_REGION`, else `AWS_DEFAULT_REGION` from the environment. Setting it under another provider is a config error. |
| `baseUrl`     | OpenAI only. The URL of a server that speaks the Chat Completions API, in place of `https://api.openai.com/v1`. Setting it under another provider is a config error. |
| `concurrency` | How many files a `standard` rule sends to the model at once. A whole number, at least `1`; defaults to `4`. Lower it when the provider rate-limits you, raise it when it does not. |
| `cache`       | Whether verdicts are cached on disk and reused for unchanged files. Defaults to `true`; `--no-cache` overrides one run. See [LLM rules](/llm-rules#verdict-cache). |
| `maxBytes`    | The largest file, in bytes, a `standard` rule sends. A whole number, at least `1`; defaults to `131072` (128 KiB). Larger files are listed as skipped and never judged. See [LLM rules](/llm-rules#large-files). |
| `maxRequests` | The most model requests one run may make. A whole number; no limit by default. A run whose plan exceeds it stops with exit code `2` before any request. `--max-requests` overrides it. See [LLM rules](/llm-rules#budget). |

Unknown keys are errors. A problem building the client, such as a missing
Bedrock region, stops the run with exit code `2` and a one-line message
before any report. A provider or credential error on a request is reported
against the file, the rule shows as `ERROR`, and the run still prints its
report before exiting `2`; see
[LLM rules](/llm-rules#provider-errors).

## Amazon Bedrock

The default. Lawbook calls the Bedrock Messages endpoint through the Anthropic
Bedrock SDK, which takes credentials from the usual AWS chain: environment
variables, a shared config profile, SSO, or an instance role. Nothing is
configured in lawbook itself beyond the region.

```yaml
llm:
  provider: bedrock
  model: anthropic.claude-opus-5-5
  region: us-west-2
```

Model ids on Bedrock carry the `anthropic.` prefix. The default is
`anthropic.claude-opus-5-5`; pick a cheaper model with `model` when a rule
runs over many files. The region must offer the model you name.

## Anthropic API

```yaml
llm:
  provider: anthropic
  model: claude-opus-5-5
```

Credentials come from the environment: `ANTHROPIC_API_KEY`, or a profile
created with `ant auth login`. The default model is `claude-opus-5-5`, and ids
have no prefix.

## OpenAI

```yaml
llm:
  provider: openai
  model: gpt-5
```

The key comes from `OPENAI_API_KEY` in the environment. Lawbook sends the
same prompt as to the other providers through the Chat Completions API with
a JSON schema response format, so `model` must be one that supports
structured outputs. There is no default model; name one.

`baseUrl` points the same client at any server that speaks Chat Completions,
such as a local model server, so a team can judge files without sending them
outside its network:

```yaml
llm:
  provider: openai
  model: llama3.3
  baseUrl: http://localhost:11434/v1
```

The server must support `response_format` with `json_schema`; one that does
not answers with a provider error. OpenAI caches shared prompt prefixes on
its own, and lawbook reports the tokens it served from that cache under
`cacheReadInputTokens`, as it does for the Anthropic providers.

## No network in tests

Both providers sit behind one `Judge` interface, and `run` accepts the
factories that build them, so a test or an embedding program can pass its own
judge and never reach a network. The package exports `messagesJudge`, the
provider-neutral core the Bedrock and Anthropic adapters wrap, and
`chatJudge`, which the OpenAI adapter wraps, for anyone adding a provider
that speaks the Anthropic Messages API or the Chat Completions API.
