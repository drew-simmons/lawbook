`lawbook check` reads the first of `lawbook.yaml`, `lawbook.yml`, or
`lawbook.json` it finds in the directory it checks, unless `--config` names a
file. JSON is valid YAML, so both formats share one schema.

```yaml
version: 1
ignore:
  - "**/node_modules/**"
  - "**/.git/**"
llm:
  provider: bedrock
rules:
  - id: no-console
    description: Production code logs through the logger
    files: ["src/**/*.ts"]
    forbid: 'console\.(log|debug)\('
  - id: spdx-header
    files: ["src/**/*.ts"]
    require: '^// SPDX-License-Identifier: '
  - id: has-readme
    exists: README.md
  - id: no-env-file
    absent: .env
  - id: errors-are-actionable
    files: ["src/**/*.ts"]
    threshold: 0.7
    standard: Every error message says what went wrong and what to do next.
```

## Top level

| Key       | Required | Meaning                                                                                      |
| --------- | -------- | -------------------------------------------------------------------------------------------- |
| `version` | yes      | Always `1`.                                                                                  |
| `ignore`  | no       | Globs no rule looks at. Defaults to `**/node_modules/**` and `**/.git/**`; setting it replaces the defaults. |
| `llm`     | no       | The model that judges `standard` rules. See [Providers](/providers).                         |
| `rules`   | yes      | The rules, run in order.                                                                     |

Unknown keys anywhere in the file are errors, so a typo cannot silently
disable a rule.

## Rules

Every rule has an `id`, which must be unique, and may have a `description`.
The rule's kind is the one remaining key.

| Kind      | Needs `files` | Fails when                                                        |
| --------- | ------------- | ----------------------------------------------------------------- |
| `forbid`  | yes           | Any line of a selected file matches the pattern. One finding per line, carrying the line. |
| `require` | yes           | A selected file does not match the pattern anywhere. One finding per file. |
| `exists`  | no            | The path is missing.                                              |
| `absent`  | no            | The path is present.                                              |
| `standard` | yes          | A model's probability that a selected file meets the prose is below `threshold`. One finding per file, carrying the model's reason and decision. See [LLM rules](/llm-rules). |

`exists` and `absent` take a single path relative to the checked directory.

### Standard rules

| Key         | Required | Meaning                                                                 |
| ----------- | -------- | ----------------------------------------------------------------------- |
| `standard`  | yes      | The standard in prose.                                                  |
| `threshold` | no       | The probability, `0` to `1`, a file must reach to pass. Defaults to `0.5`. |

### Patterns

`forbid` and `require` are JavaScript regular expressions compiled with the
`m` and `u` flags, so `^` and `$` match at line boundaries and the pattern must
be valid Unicode-mode syntax. Quote patterns with single quotes in YAML so
backslashes survive. An invalid pattern stops the run with exit code `2`.

### Selecting files

`files` is a list of globs relative to the checked directory. Globs follow the
usual conventions: `*` matches within a path segment, `**` crosses directories,
and `{a,b}` lists alternatives. Dotfiles and dot directories are included, so
`.github/**/*.yml` works; the default `ignore` keeps `.git` out.

A rule whose globs select no files passes. Selected files are read as UTF-8
text.

`lawbook check --files`, `--changed`, and `--since` narrow every `files`
rule to the files they name, so a pre-commit hook or a pull request check
looks only at what changed. See
[Commands](/commands#checking-a-subset-of-files).
